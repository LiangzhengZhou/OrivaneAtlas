# ADR0097 — Local derived File processing and restart recovery

2026-10-14. FINAL Phase15 and section65 require asynchronous extraction/indexing without opening every remote original. The durable original File plus its source version/hash is the pending work source; a local derived processing journal records leases, bounded errors and successful index identity. It does not change original File versions, original mutation receipts or AI consent.

Processing runs only for originals already available in the local blob store. Remote metadata does not trigger binary downloads. Upload completion and explicit original hydration wake the worker; restart scans metadata and resumes unfinished local work. Explicit preview can retry a failed source. A source-version/hash/index-version key prevents stale success or failure from replacing newer work. Claim and finish are owner-authorized IndexedDB transactions, with expiring leases to coordinate windows/restart. Derived chunks remain published atomically through the existing extraction store. No WebView timer is represented as a native Notification scheduler.

Application owns eligibility, bounded processing and error classification; bootstrap only assembles ports and wakes the worker. UI reads derived processing facts, never fabricates READY flags. The processing journal is local derived state inside existing entities storage, not an additional business collection or sync command. Existing append-only extraction migrations remain; no historical migration changes. Acceptance requires real restart/lease/auth/stale/failed retry tests and production browser upload-to-search without opening File Detail.
