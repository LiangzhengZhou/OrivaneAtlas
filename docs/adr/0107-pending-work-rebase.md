# ADR0107 — Pending Work rebase preserves immutable transmission evidence

2026-10-15. FINAL Phase11/12 requires pull → rebase → push and forbids silent last-write-wins. A never-transmitted singleton work.update with a known base may be superseded only after a clean three-way field/Markdown merge. The patch must match original recorded intent. Lifecycle/compound commands, absent bases, conflicting fields and attempted requests remain untouched for recovery/review.

Application prepares a new stable command ID and patch against the pulled canonical version. IndexedDB commits the merged local row, replacement command and Outbox, workspace revision and superseded original evidence in one strict transaction. The original command remains immutable. CAS checks identity/device, full binding, current row, canonical base, workspace revision, singleton pending group and replacement identity. A crash cannot remove the original before the replacement exists. Previously sent requests always retain their original key and bytes for receipt lookup; no network request occurs inside the storage transaction.

The coordinator uses this port after canonical pull and receipt recovery, before claiming transmission. Bootstrap wires the real IndexedDB adapter. This decision does not implement epoch recovery, general conflict review or workspace merge/new-remote-workspace creation. Those remain required. Generic durable metadata collections suffice; no historical schema or release metadata changes.

240 extension in progress: explicit Work conflict review is separate from automatic rebase. Captured binding/revision/old mutation/command/current/canonical base must match fresh reads exactly. Human chooses local or remote values for the original patch; both create a new canonical version-checked command, retaining original conflict evidence. Runtime looks up the old receipt and refreshes canonical delta first. Previously transmitted non-conflict requests remain in recovery, never in automatic rebase. Other conflict families and epoch recovery are not claimed complete.

272–273 extension: unresolved/unsupported earlier commands block later transmission of the same entity during a synchronization pass, including a conflict produced during that pass. Compound commands propagate the block to their entire entity footprint. Unrelated entities can continue. Receipt recovery is still read-only and retains original bytes.

A reviewed conflict may have later never-sent singleton commands of the same family. These are not squashed or silently replayed. Application checks exact payload/base continuity, actor/device, causal order and pending attempts. The captured review includes those successors. Replacing the predecessor retains its original causal position, preserves the current later local row/body/projections and every successor byte, and records superseded predecessor evidence in the same strict transaction. The adapter CAS checks the complete pending set and current later row. After explicit predecessor resolution, successors either synchronize normally or receive their own conflict review. No optimistic entity version is lowered or reused to overwrite the later local master. Unsupported/mixed/transmitted successor chains remain blocked.
