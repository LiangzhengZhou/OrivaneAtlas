# ADR0109 — Pre-merge original archives and reviewed conflict replacement

2026-10-15. FINAL Phase12/13 requires that merge preparation never replace the source workspace or rewrite transmitted commands. Portable archives use the existing credential-excluding ORIVANE1 format and include original File/image bytes. An independent IndexedDB database retains immutable archives plus source workspace/principal/revision and destination origin/workspace/principal/epoch/revision. Scope and source revision are checked before and after archive creation and durable write; readback hash is verified. Interrupted preparation can leave a valid retained archive, but never authorizes import. Offline recovery lists only the current local workspace/principal's backups and validates bytes again on download. Workspace selection and restore do not replace the archive database. Future deletion/retention must be explicit; no automatic cleanup is introduced.

Reviewed File rename conflicts reuse the existing atomic replacement mechanism. Never-sent disjoint changes may rebase; transmitted same-field conflicts require an explicit captured review, original receipt lookup and fresh canonical pull. File originalName/contentHash/blob identity are immutable. Replacement commands use a fresh stable ID and canonical version, with original commands and superseded conflict evidence retained. Work and File command/collection pairings are checked in the adapter; source identity, device, binding, revision, base and original Outbox are checked in the same strict transaction. Remote delete/compound/Markdown/order conflicts are not implicitly resolved by this rename path.

A saved backup, a selection plan, an owned empty remote workspace or a reserved local catalog entry is not a completed import. Actual import must validate complete references, handle original bytes, preserve recovery evidence, conditionally apply to the reviewed destination and only then activate the intended replica. No production data or servers are involved in local validation.
