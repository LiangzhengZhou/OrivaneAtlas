# ADR0029 — Reviewed additive plans and calendar occurrences

Accepted 2026-09-17. Implements an additive Manifest v1: explicit JSON task entries with temporary IDs and dependency references, a selected existing project, strict fields and bounded size. Markdown remains content, never parsed into tasks implicitly. Preview validates names, dates and DAG and stores a versioned proposal only. Human publication binds proposal version, creator, policy version and the exact workspace graph revision vector (sorted Work IDs/versions and edges). Every ordinary graph mutation changes this vector; stale previews cannot publish. Editing produces a new preview, never reuses approval. Publication uses WorkService within one existing transaction, stores resulting IDs plus imported-field provenance, and is idempotent by proposal ID/version in addition to HTTP receipts. Partial publication rolls back. v1 does not edit/delete existing tasks. Integration tokens cannot approve publication.

Recurrence separates definitions from dated occurrences. Supported calendar rules are DAILY/WEEKLY/MONTHLY with positive intervals; month-end dates skip months without that day. Dates use the definition's IANA timezone, never a fixed offset. A bounded explicit generation request records past slots as MISSED without creating work; the current local day creates at most one task. Future slots are rejected. Explicit backfill creates a task for a missed slot and records completion time separately from recording/backfill time. Existing generated tasks are never silently duplicated or rewritten when definitions change. Initial scope is user-triggered generation, not a durable background scheduler.

SQLite15/PG7 add a versioned workflow record store (closed PLAN/RECURRENCE/OCCURRENCE kinds with typed application payloads) and dedicated Activity/Outbox. Payloads are versioned structured workflow documents, not dynamic business properties or credential storage. Workspace/creator foreign keys and CAS apply; soft deletion is retained. Occurrence identity is deterministic definition ID plus date; the existing workspace transaction serializes competing generation/backfill/publication. Active Work items remain in normal relational tables. No full RRULE parser, MCP transport, provider fallback or arbitrary agent execution is implied.
