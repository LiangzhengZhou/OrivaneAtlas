# ADR 0140：旧版图片缓存的服务端授权再验证

日期：2026-10-26。状态：已实施（本地测量与真实浏览器验证完成；生产远端时延未测量，未部署）。

## 背景

ADR 0134 为旧版 Library 图片建立了派生本地缓存（`$local.legacyImage` + 内容哈希 blob），但其读取策略是：离线才使用缓存，在线总是重新下载原始字节，以便服务端继续执行 Workspace/Space 授权。Session303 对“文档图片重新打开”的实测（Playwright，本地宿主，PNG 329818B / JPEG 11549B / WebP 4844B 各一张）：

- 首次授权打开：3 次 `/api/library/asset` 请求，本地下载 7–19ms/张；
- 同内容在线重新打开：仍下载全部 3 张（约 347KB 字节），随后重复哈希、写 blob、提交缓存；
- 离线重新打开：0 请求，缓存命中，图片解码/呈现与在线接近；
- 图片解码（blob → `load`）约 4–7ms/张，不是主要瓶颈；本地宿主上在线与离线打开差异约 100–250ms，远端部署会随 RTT 与图片体积放大。

因此“重新打开慢”的主要可改进点是：在保持服务端在线授权检查的前提下，避免重复传输未变化的原始字节。

## 决策

1. 服务端新增只读端点 `GET /api/library/asset/meta?id=...`（`/api/v1` 别名同步）：
   - 与字节端点完全相同的 `db.request(..., s.asset(id), requireAccess)` 授权检查；
   - 返回 `{ id, mime, size, contentHash }`，`contentHash` 为原始字节 SHA-256（与本地派生缓存同一算法）；
   - 不返回图片字节，不写数据库、不产生业务事件。
2. 客户端 `readLegacyImage` 增加可选 `revalidateCache(binding, contentHash)` 端口：
   - 在线且已有缓存记录时，先请求元数据端点；仅当服务端哈希与本地缓存一致才使用本地 blob（仍校验 blob size/mime/SHA-256 与 raster 头）；
   - 哈希不一致、缓存损坏或端点返回 404/405（旧服务器）时回退到原有下载路径，并重新校验/写入缓存；
   - 401/403 或任何授权失败直接抛出，**不回退到本地缓存**，保持 ADR 0134 的在线拒绝语义；
   - 下载得到的字节若与缓存哈希一致，跳过重复写 blob 与 replica 提交；离线路径保持原样。
3. 原生客户端只读路由允许列表加入该元数据路径；OpenAPI 双别名、`ownerSession`/`integration` 安全声明与加载文案同步。
4. 不在本 ADR 内引入新的缓存层、ETag 协议、后台预取或正文图片并行度改造；解码优化留待有证据时再做（本次测得解码仅 4–7ms/张）。

## 影响

- 在线重新打开未变化的旧版图片：由“下载全部字节”变为“一个小的授权元数据请求 + 本地读取”；服务端仍需读取/哈希字节，节省的是网络传输与重复本地写入。
- 首次打开、图片内容变化、旧服务器、离线场景行为不变；在线拒绝仍失败关闭。
- 真实远端（生产域名）尚未测量/部署，不能对外宣称生产速度已改善；本地证据与请求计数见 Session303 记录。
