# ADR0105 — Explicit workspace binding review

2026-10-15, implementation in progress. FINAL8/Phase13 forbids login-triggered merge or replacement of the durable local workspace. Account authentication and workspace binding are separate actions. A metadata-only preview records both revisions and reports counts, exact/possible duplicate groups, ID collisions, project hierarchy, task membership, document title/alias collisions and original File hashes. Body-unloaded manifests cannot prove exact Markdown duplicates, regardless of matching title or length. Preview output never returns body content and does not write entities, identity, sync state or Outbox.

Application owns this comparison. Bootstrap owns authenticated transport and consistent local reads; UI must show explicit account-workspace, merge, new-sync-workspace or defer choices. Applying a reviewed choice still requires detached identity, generation and revision CAS, a retained original local workspace and atomic durable binding. Preview alone is not authorization or a completed binding workflow. Legacy startup Login must not be restored to make older browser tests pass. Connection/catalog/application and UI wiring, recovery, collision resolution and full acceptance remain required.

237: comparison groups carry collection identity. Explicit merge selection requires a decision for every live source record, never infers reuse from title/unloaded bodies, and validates parent/project/space mapping consistency. This is a pure selection plan; it does not authorize backup/import or bypass canonical Application commands. Runtime B/C application remains open.
