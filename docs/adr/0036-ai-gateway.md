# ADR0036 — Registered personal Gateway, durable reservations and bounded fallback

Accepted 2026-09-18. Provider/model/capability registrations and versioned policy live in the existing AES-GCM personal vault, scoped by workspace, principal and project/space. A registration includes stable provider identity, enabled state, capabilities, selected capability, explicit daily request and USD budget policies, prices in integer micro-USD per million tokens, and at most two ordered fallback profile IDs. Missing legacy policy preserves legacy limits; it is not interpreted as permission to spend under a newly configured finite budget. UNLIMITED is an explicit policy value, independent of time/input/output bounds and human approval.

AgentRun remains the durable request and ledger record, using existing JSON storage and CAS transactions with Activity/Outbox. Reserve before network dispatch; check the current UTC-day principal/scope ledger across profiles, including unresolved reservations. Reserve conservatively using four input tokens per UTF-16 code unit plus 4096 protocol tokens and the configured output bound, taking the largest approved route estimate. This is a conservative estimate, not a provider invoice or guaranteed tokenizer bound. Actual reported usage reconciles against immutable approved prices; overruns remain recorded and block later budget admission. Missing usage, interrupted sends and unknown outcomes retain the full reservation. A definitive no-send releases it. Legacy unpriced consumption blocks a finite monetary budget for that day rather than silently counting zero. Restart retains reservations. SQL schema is unchanged; take an existing database and vault backup before upgrade, verify JSON round-trip and restoration; downgrade to code ignoring budgets is unsupported.

Approval snapshots the exact ordered fallback route fingerprints. Every candidate rechecks authenticated access, persisted run/context/data policy and current vault identity. A removed, changed or disabled registration invalidates approval. Only a trusted adapter's typed NOT_SENT error permits the next candidate; network timeout, cancellation, HTTP error or an unknown post-send outcome never retries. There are at most three candidates and one overall deadline. DNS/private-address rejection is NOT_SENT, but no redirect or private-network exception is introduced. Model credentials never enter AgentRun or ordinary database storage.

Text, strict JSON output and embedding are explicit capabilities. Embeddings use the same public HTTPS pinned-DNS transport and return a bounded JSON vector artifact, not executable tools. No provider tool calls execute automatically. API authentication, CSRF, idempotency and independent audit remain host responsibilities. Registry summaries and ledger projections are safe to expose only to the authenticated owner. Tests use mocked providers exclusively and must cover encrypted reopen, revocation, budget concurrency/CAS, unknown usage, explicit unlimited, fallback boundaries and isolation.

## Exact host integration (main agent owns server and public exports)

- Export `gateway-policy` from the application entrypoint. No SQLite18 DDL/store constructor is necessary: existing `agent_run.payload` JSON and transaction stores persist `AgentRun.attempt.money`, the approved `route.gateway` and `route.fallbackRoutes` without a migration. The vault constructor remains `openPersonalVault(directory)`.
- In `/api/ai/providers/save`, add `"gateway"` to the input keys allowlist. Keep human-only, current-access, CSRF and request-ID checks; `vault.save` validates the policy and the entire registry relationship. Existing `runtime.saveProvider` already transports the typed optional field. GET providers now returns safe registrations with capability/policy and fallback snapshots.
- In the `executeApprovedModel` authorization callback change `() => db.request(...)` to `(route) => db.request(...)`. After checking the current persisted version/status, call `validateApprovedContext(actor, { ...current, route }, notes, library)`. This ensures every fallback repeats all data checks against its own provider.
- Capture `result.settlement` alongside `result.usage`, and pass it as the final optional argument to `ConnectedService.finish(actor,id,output,error,interrupted,usage,settlement)`. Import type `GatewaySettlement` for the local variable. On errors before dispatch it may be omitted (retains reservation); on startup recovery omit it (unknown remains charged).
- Existing `/api/ai` GET already returns the persistent run ledger fields. If providing a separate ledger endpoint, use `gatewayLedger(runs.filter(run => run.createdBy === context.principalId && run.workspaceId === context.workspaceId))`; no secrets are included. Public schemas must define the optional `gateway`, `fallbackRoutes`, `attempt.money`, and the explicit `UNLIMITED` limit string. No new unauthenticated routes or external tool permissions are required.
- Existing `PersonalAISettings` mounts `GatewaySettings`; existing `ConnectedViews` displays approved alternatives and persisted reservations. No App/bootstrap changes are needed for this UI. MCP stays with main integration.
- Remove the lifetime `connected.runs().length >= 1000` proposal gate; it contradicts explicit UNLIMITED daily requests. Keep independent existing HTTP rate limits, bounded inputs, owner-scoped simultaneous-run admission and finite runtime constraints. Paginate history rather than making 1000 lifetime requests permanently disable AI.
