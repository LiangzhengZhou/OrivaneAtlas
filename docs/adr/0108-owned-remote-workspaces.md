# ADR0108 — Owned remote workspaces and scope selection

2026-10-15, implementation in progress. FINAL8 option C creates a real additional workspace owned by the authenticated human principal. It does not create another account, AI Project or mutable local identity. Workspace creation is independently idempotent; original local metadata, pending commands and bytes are retained. An explicit preview and durable backup precede importing reviewed content. Activation follows successful preparation; a reservation is not activation.

The server keeps an ownership directory, separate from ordinary workspace membership. Existing account-default workspaces remain owned by their existing account; no ownership is inferred from arbitrary membership. SQLite and PostgreSQL append ownership migrations together. Creating a workspace also creates owner membership and a connected Activity/Outbox event in the same transaction. Account/session authorization is rechecked inside mutations; clients cannot assert ownership by sending an ID.

Workspace scope must be explicit per request and validated against this directory. A mutable shared-cookie selection must not switch unrelated browser tabs or replay pending commands into a different workspace. Browser and native JSON/binary transports must preserve the selected scope; credential tokens remain workspace-scoped. No claim of complete option C until server authorization, transport, local preview/backup/import, catalog activation and recovery are wired and tested. Source data and production servers are never changed during local verification.
